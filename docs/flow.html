LLM gateway: how a request flows

From config/boot.rb through the two bin/ entry points to the provider that answers.

1. Boot2. Gateway3. bin/onboard4. bin/search5. Errors

1. Boot: config/boot.rb

flowchart TD
  A["bin/onboard · bin/search"] --> B["require config/boot"]
  B --> C["BUNDLE_GEMFILE ||= repo Gemfile
require bundler/setup"]
  C --> D["stdlib: json, logger, net/http, singleton
ActiveSupport indifferent access"]
  D --> E{"Rails defined?"}
  E -- no --> F["Rails.logger shim
stderr, LOG_LEVEL (default warn)"]
  E -- yes --> G
  F --> G["OLLAMA_SERVER_ADDRESS ||= http://localhost:11434"]
  G --> H["require app/services in dependency order"]
  H --> H1["1. providers
OllamaService · OpenaiProvider · GeminiProvider"]
  H1 --> H2["2. factory
AiService"]
  H2 --> H3["3. base assistants
AiAssistant → Gemini / Openai / Ollama Assistant"]
  H3 --> H4["4. mode subclasses
*ProjectAssistant · *OnboardingAssistant"]
  H4 --> H5["5. services
SummarizerService"]
  H5 --> Z["require demo/cli (+ demo/report and demo/semantic_search for bin/search)"]
  • Controllers under app/controllers are never loaded. The shell is only the slice of Rails the services needed.
  • OllamaService reads LLM, EMBEDDING_MODEL and OLLAMA_SERVER_ADDRESS into constants at require time, so set them before launching.

2. The gateway: AiService

flowchart LR
  ENV["ENV AI_PROVIDER
(default ollama)"] --> P["AiService.provider
memoized"]
  P -->|openai| OP["OpenaiProvider
chat · completion · embedding"]
  P -->|gemini| GP["GeminiProvider
completion · parse_completion
embedding raises NotImplementedError"]
  P -->|anything else| OS["OllamaService
chat (streaming Enumerator)
completion · embedding"]
  CALLERS["AiService.completion / chat / embedding / parse_completion"] --> P
  CP["AiService.current_provider
case provider.name → 'openai' | 'gemini' | 'ollama'"] --> F{"assistant factories"}
  F -->|project_assistant| PA["Openai / Gemini / Ollama ProjectAssistant"]
  F -->|onboarding_assistant| OA["Openai / Gemini / Ollama OnboardingAssistant"]
  AF["assistant_for(mode)
'project' | 'onboarding' | else ArgumentError"] --> F
  • Plain calls (completion, chat, embedding) go through AiService.provider. Assistants are picked by current_provider, then call their own provider directly.
  • The Ollama assistants reuse the Gemini system prompts.

4. bin/search: enrichment-based semantic search

flowchart TD
  S["bin/search QUERY [--compare], or bin/search --eval"] --> A{"arguments valid?"}
  A -- no --> U["abort with usage"]
  A -- yes --> R["Demo::CLI.run (key check for AI_PROVIDER)"]
  R --> EP{"EMBEDDING_MODEL_PROVIDER"}
  EP -- "gemini or unknown" --> X["abort: use ollama or openai"]
  EP -- "set, else follows AI_PROVIDER, else ollama" --> K["key check for the embedding provider"]
  K --> H["header: Enrichment: provider (model) · Embeddings: provider (model)"]
  H --> CP["cache file per enrichment model + embedding model"]
  CP --> LC{"cache valid for these people?"}
  LC -- yes --> READY["index in memory"]
  LC -- no --> EN["per person: enrichment via AI_PROVIDER
SummarizerService: summary + related terms"]
  EN --> V["embed bio + enrichment, and bio alone
via the embedding provider"]
  V --> READY
  READY --> M{"mode"}
  M -- query --> Q["top 5 with score and strength (σ)
divider before weaker matches"]
  M -- "--compare" --> C["rank and score with and without enrichment
↑n / ↓n movement
flag only strong (≥ +1.5σ) matches the bare bio ranks below 5"]
  M -- "--eval" --> E["demo/queries.json: best rank of the expected people
hits at #1 and in the top 5; helped / hurt / same"]
  • Enrichment runs once per profile for each enrichment-and-embedding model pair; a query costs one embedding call.
  • Strength is measured against each query's own scores, so the cutoff works for any embedding model.
  • Ties keep people.json order, so results are stable between runs.

5. Errors: Demo::CLI.run

flowchart TD
  R["Demo::CLI.run"] --> K{"openai/gemini and API key missing?"}
  K -- yes --> KM["print 'needs OPENAI_API_KEY / GEMINI_API_KEY', exit 1"]
  K -- no --> Y["yield the script body"]
  Y -->|Interrupt| I["newline, quiet exit"]
  Y -->|StandardError or NotImplementedError| EM["error_message(e)"]
  EM --> T{"Ollama::Errors::RequestError?"}
  T -- "HTTP 404" --> M1["'Run: ollama pull LLM (and EMBEDDING_MODEL)'"]
  T -- "ConnectionFailed / Timeout" --> M2["'Can't reach Ollama at …, run ollama serve'"]
  T -- "other HTTP" --> M3["'Ollama returned HTTP status: body'"]
  EM -->|NotImplementedError| M4["its message (e.g. Gemini embeddings)"]
  EM -->|anything else| M5["Class: message"]
  M1 --> X["warn, exit 1"]
  M2 --> X
  M3 --> X
  M4 --> X
  M5 --> X
